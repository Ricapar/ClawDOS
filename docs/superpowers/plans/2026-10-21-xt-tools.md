# XT Tool Calls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the model call a fixed set of tools that CLAWDOS.EXE runs on the XT.
The tools cover files, system info, running DOS programs, CGA drawing, PC
speaker music, memory and port access, and coloured text art.

**Architecture:**
- The bridge runs the tool loop for both the Anthropic and OpenAI-compatible
  APIs, and holds the tool schemas.
- It sends each call to the XT as `TOOL`/`ARG`/`CALL` lines and waits for
  `OUT`/`DONE`.
- CLAWDOS.EXE dispatches each call to an executor in `lib/`, asks permission
  in safe mode, and shows Claude Code-style transcript lines.

**Tech Stack:** Python 3.13 asyncio bridge (`anthropic` SDK, `httpx`), OpenWatcom 2 C/C++ for 8086 (large model), mTCP, DOSBox-X and 86Box for testing.

**Spec:** `docs/superpowers/specs/2026-10-21-xt-tools-design.md`

## Global Constraints

- 8086 instruction set only (`wcc/wpp -0`). CLAWDOS.EXE builds with the large model (`'model': 'l'`).
- All screen output goes through `lib/screen` and `lib/console`. The exceptions are the `run` and `draw` executors, between `scr_suspend` and `scr_resume`.
- Server lines carry at most 500 payload bytes (`MAX_TXT`). The XT receive buffer is 1024 bytes and XT send payloads are at most about 1000 bytes, so `OUT` chunks are at most 400 raw bytes before escaping.
- Escaping in `ARG`/`OUT`: `\n` means newline and `\\` means backslash. On the XT, other bytes below 0x20 (except tab) become `.` when sent.
- A tool result is at most 4096 bytes on the XT. Arguments total at most 6144 bytes.
- Tool statuses are exactly `ok`, `error`, `denied`, `stopped`.
- Classes: R = `sysinfo dir read peek`. H = `draw play textart`. W = `write delete mkdir rename run poke port`.
- At most 25 tool rounds per user message (`MAX_ROUNDS = 25`).
- Code linking mTCP is GPLv3. Watcom: no quoted `-D`, and wlink takes `.lnk` files.
- Commit to main after each task, ending the message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Esc during a tool, then sending a new message.** The next message must not get an API 400 for a dangling `tool_use`. Covered by `test_stop_mid_tool_then_continue` in Task 3 and `test_settle_after_cancel` in Task 4.
2. **Paths with spaces or lowercase, and wildcards passed to `delete`.** DOS 8.3 rules mean the executor must return a clear DOS error, not crash. Covered by tour items in Task 7 (lowercase path, missing file).
3. **`run` of a program that leaves the screen in another video mode** (e.g. `MODE CO40`). The chat must come back intact. Covered by the Task 11 86Box check with `MODE CO40`.
4. **A huge `draw` or `play` argument** (several KB, split over many `ARG` lines). It must arrive whole. Covered by `test_long_arg_chunks` in Task 3, and by a 3 KB script in Task 10's tour.
5. **The model's text ending mid-line right before a tool call.** The tool header must start on its own line. Covered by the `!tool` scenario, which streams text without a trailing newline before calling (Task 3), and checked visually in Task 7.

### Task 2: Tool schemas and line encoding (`bridge/tools.py`)

**Files:**
- Create: `bridge/tools.py`
- Test: `bridge/test_tools.py` (new; runs with `python bridge/test_tools.py`)

**Interfaces (produces):**
- `TOOLS: list[dict]`. Each entry is `{'name', 'description', 'params': {key: (description, required: bool)}, 'cls': 'R'|'H'|'W'}`, for the 14 tools in the spec's catalog with the spec's argument names.
- `anthropic_tools() -> list[dict]` (`name`, `description`, `input_schema` with all params `type: string`). `openai_tools() -> list[dict]` (`{'type': 'function', 'function': {...}}`).
- `stringify(args: dict) -> dict[str, str]`. Numbers become decimal, bools become `'1'`/`'0'`, `None` is dropped, and anything else becomes `str()`.
- `escape(s: str) -> str`, `unescape(s: str) -> str`.
- `call_lines(id: str, call: ToolCall) -> list[tuple[str, str]]` yields `('TOOL', 'id name')`, then `('ARG', 'key chunk')` pairs, then `('CALL', '')`. Each escaped chunk is encoded with `to_cp437` and must fit 500 bytes, including the key and a space.
- `@dataclass ToolCall: name: str; args: dict[str, str]; id: str = ''; result: ToolResult | None = None`.
- `@dataclass ToolResult: status: str; text: str`, with `model_text() -> str`:
  - ok: `text`
  - error: `'Error: ' + text`
  - denied: `'The user denied this tool call.'`
  - stopped: `'Interrupted by the user.'`
- `summary(call) -> str`: `[read C:\AUTOEXEC.BAT -> ok]`, using the tool's header key as in the spec's transcript section (path / command / addr / port / from). When the call has no such argument, it's `[sysinfo -> ok]`.
- `MAX_ROUNDS = 25`.
- `TOOLS_PROMPT: str`, the spec's system-prompt paragraph. It includes these exact phrases: "real IBM PC XT", "GW-BASIC", "may be denied".

Tool descriptions must tell the model the formats the executors parse:
- `addr` is hex `seg:off`.
- `port` is hex.
- `value`/`len` are decimal or `0x` hex.
- `bytes` are hex pairs separated by spaces.
- `draw` lists the supported statements, and `play` the PLAY commands.
- `textart` explains `~X`.
- `run` warns: no network programs, at most 120 characters.

### Task 4: Anthropic tool loop and history settling

**Files:**
- Modify: `bridge/providers.py` (`AnthropicChat`, `transcript`, `system_prompt`)
- Test: `bridge/test_bridge.py` (new class `AnthropicTools`)

**Interfaces:**
- Consumes: Task 2's `anthropic_tools()`, `ToolCall`, `ToolResult.model_text()`, `summary`, `MAX_ROUNDS`, `TOOLS_PROMPT`.
- Produces:
  - `system_prompt(p)` ends with `TOOLS_PROMPT`.
  - `AnthropicChat.reply(text)` loops:
    1. Each round streams with `tools=anthropic_tools()`. On the round that hits the `MAX_ROUNDS` cap, it also passes `tool_choice={'type': 'none'}` and appends a text block, `Tool limit reached; answer now without tools.`, to the trailing tool-result message.
    2. It appends the assistant's `echo_blocks(final.content)`.
    3. If `stop_reason == 'tool_use'`, it yields a `ToolCall(block.name, stringify(block.input))` for each `tool_use` block, in order. It appends one user message whose content is a list of `{'type': 'tool_result', 'tool_use_id', 'content': result.model_text(), 'is_error': status != 'ok'}`, then starts the next round.
  - `AnthropicChat._add_user(text)`: if the last message is a user message (tool results), it appends `{'type': 'text', 'text': text}` to its content list. Otherwise it appends a new user message.
  - `AnthropicChat._settle(start, merged)`, called from `except BaseException` (including `GeneratorExit` and `CancelledError`):
    - If no assistant message was added since `start`, it removes the user text (pops the message, or removes the merged text block). This is today's behaviour.
    - Otherwise, if the last message is an assistant message with `tool_use` blocks, it appends a user message with tool_results for those ids. Results already collected keep their content, and the rest get `Interrupted by the user.` with `is_error: True`.
  - Refusal: `_settle`, then `raise Refused`. With `max_tokens`, it yields the cut-off note and ends.
  - `transcript(chat)` returns a strictly alternating user/assistant list:
    - A user message made only of tool results is folded into the preceding assistant entry.
    - Each `tool_use` becomes `summary(...)` text; a dict `{'type': 'tool_use', 'name', 'input'}` and SDK block objects are read alike via a `_get(block, key)` helper.

Behaviour that must match the spec:
- **Dispatch table entries:** `{name, title, headerKey, cls, busyVerb, fn}`.
- **Transcript lines:**
  - Before the header, the reply is closed out with `blankLine()`.
  - Header: bullet plus `Title(arg)`, clipped to 76 columns.
  - Summary: `note()` with `\xC0`, in red for errors and denied. Denied reads `Denied by user`.
- **Permission:** only for class W with safe mode on, via `ui_ask("Allow Title(arg)? (y/n)")`.
- **`write` preview** via `ui_tool_detail`, e.g. `12 lines, 340 bytes, overwrites existing file` (or `new file`, or `appends`).
- **After a call:** send `OUT` chunks (≤ 400 raw bytes each, escaped), then `DONE id status`, and on stopped also `STOP`. On truncation, append `\n...(truncated)` to the result.
- **Unknown tool:** `DONE id error` with `OUT unknown tool NAME`.
- **`-q` flag:** after the `-m` message's reply ends (END/ERR) and state is idle, exit as `/quit` would. It sets `unattended=1`.
- **Executor specifics** (spec "File tools", "Tool catalog"):
  - `read` defaults: `start=1`, `lines=100`. Text lines are prefixed `%5u `. The summary is `N lines`, or `N bytes (hex)` for binary files.
  - `dir` caps output at 150 entries plus `+N more`, checking `tool_esc()` between entries. The summary is `N entries`.
  - All file tools refuse paths over 64 characters (`path too long`).
  - `write` turns `
` into CRLF.
  - `read` treats a file as binary if its first 512 bytes contain a NUL or more than 10% control bytes other than tab, CR, LF and EOF (0x1A).
  - `textart` writes with `con_attr`. `~X` sets foreground X (hex), `~~` is a literal `~`, lines are clipped at 78 columns, and output stops at 40 lines.

### Task 8: `play`: the PLAY parser and the PC speaker

**Files:**

**Interfaces:**
```c
typedef struct PlayOps { void *ctx;
    void (*tone)(void *ctx, unsigned hz, unsigned ms);   /* hz 0 = silence */
    int  (*stop)(void *ctx); } PlayOps;                  /* checked between notes */
int play_run(const char *music, const PlayOps *ops, unsigned long *total_ms,
             char *err, int errlen);                     /* 0 ok, 1 stopped, -1 error */
```
**Semantics:**
- Note number `n = octave*12 + semitone + 1` (C=0 … B=11), and `hz = round(440 * 2^((n-46)/12))`, so O3 A = 440 Hz and middle C = O3 C. `N0` is a rest.
- Defaults: `T120 L4 O4 MN`. Duration in ms = `240000 / (T * L)`, ×1.5 when dotted.
- `MN` plays 7/8 of the duration and is silent for the rest. `ML` plays the full duration. `MS` plays 3/4. Rounding: `on = dur*k/8` floored, `off = dur - on`, and `tone(0, off)` is emitted only if `off > 0`.
- `<`/`>` clamp the octave to 0..6. `#`/`+` raise a semitone and `-` lowers one. `MF`/`MB` are ignored, and spaces are ignored.
- Ranges: T 32–255, L 1–64, O 0–6, N 0–84. Out of range gives `col N: T out of range`, and an unknown character gives `col N: unexpected 'X'`, with 1-based columns.

`sound.c`:
- `tone()` programs PIT channel 2 (mode 3, divisor 1193182/hz) and gates port 61h bits 0–1.
- Waits use a PIT channel 0 latch read: sum `(prev - cur) & 0xFFFF` per poll, with 2386 counts per ms in mode 3, polled in a tight loop.
- `stop` is `tool_esc()`.
- The speaker is always turned off on every exit path.
- Summary: `played 8.2s` or `stopped by user`.

### Task 10: `draw`: CGA graphics plus screen suspend and resume

**Files:**
- Modify: `lib/screen.h`, `lib/screen.c` (`#define SCR_SAVE_BYTES 16384`, `void scr_suspend(unsigned short *save)`, `void scr_resume(const unsigned short *save)`)

**Semantics:**
- `scr_suspend` saves the full 16 KB (or the 4000-byte page without hardware scrolling), the CRTC start address, and the cursor position and shape, then sets mode 3.
- `scr_resume` sets mode 3, restores the memory, start address and cursor, and leaves the footer rows as they were in the saved memory. The caller then calls `ui_redraw()` to repaint the footer.
- `gfx` plots straight into CGA memory:
  - Mode 4: offset `(y&1)*0x2000 + (y>>1)*80 + (x>>2)`, 2 bits per pixel, MSB first.
  - Mode 6: `x>>3`, 1 bit per pixel.
  - `COLOR` writes port 3D9h. `text` uses INT 10h AH=02h and AH=0Eh with BL = colour.
  - `paint` is a scanline fill with a 512-entry explicit seed stack (malloc'd), returning -1 on overflow, which becomes `PAINT: area too complex`.
- `tool_draw`:
  1. Suspend the screen and set SCREEN 1.
  2. Run `bas_draw`.
  3. Hold until a key is pressed, or 3 s when unattended. A key held during drawing does not count; drain the buffer first.
  4. Resume the screen.
  5. Summary: `drawn, viewed Ns`, or the error with `t->summary` set to the error text. Status is error on an error and stopped on Esc.
  6. The result text is the summary, plus `stopped at line N` when stopped.
