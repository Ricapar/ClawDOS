Dev tools: TINYASM WASM JWASMR TCC BCC GWBASIC LDEBUG
All tested on this 8088 at 4.77 MHz; times are for a hello program. Write the
source with the write tool, then build and run it with the run tool. Working
examples of each are in C:\TESTS\DEV (T*.ASM, H*.C, T*.BAS).

MEMORY: a run gets about 190 KB (what sysinfo shows). Set full_memory true
and ClawDOS steps out of memory while it runs, giving about 450 KB, but each
such run costs several seconds on the 8088 (ClawDOS reloads and reconnects).
Use it for TCC, TLINK, MAKE, the assemblers, programs you just built, .BAT
files, and anything that said "out of memory"; leave it off for DIR, TYPE
and quick checks. Give run a program and its arguments (TCC -c X.C): that
starts it directly. A .BAT file, redirection (> <) or a built-in (DIR, TYPE,
CD) loads a second COMMAND.COM and costs 70 KB. There is no & or &&: put the
steps on separate lines of one run call instead (compile, compile, link);
they stop at the first that fails.

EDITING: change a few lines with edit (old text -> new text) instead of
rewriting the whole file with write; find things with search, not FIND.
Keep sources split into small files (TCC runs out of memory on big ones).

ASSEMBLERS (they write a .COM directly, no linker needed)
- TINYASM -f bin X.ASM -o X.COM [-l X.LST]
  NASM syntax; start .COM programs with org 0x100. Errorlevel 1 on errors.
  About 5 s. Out-of-range conditional jumps are not lengthened for you:
  invert the test and use jmp.
- WASM X
  Wolfware Asm, MASM-like syntax, makes X.COM (origin 100h is automatic).
  About 5 s. Manual: C:\DEVEL\DOC\WASM\WASM.TXT
- JWASMR -bin -FoX.COM X.ASM
  JWasm: full MASM syntax (.model tiny / .code / org 100h / end start);
  -mz instead of -bin makes an .EXE. About 18 s; very big sources can run
  out of memory.

C COMPILERS
- Turbo C 2.0 (ANSI C), in two steps (two lines of one run call): compile, link.
    TCC -c X.C                                       makes X.OBJ
    TLINK C:\TC\LIB\C0S X,X,NUL,C:\TC\LIB\CS          makes X.EXE (small)
  For a .COM: TCC -mt -c X.C, then TLINK /t C:\TC\LIB\C0T X,X,NUL,C:\TC\LIB\CS
  Plain "TCC X.C" also links, by starting TLINK while TCC is still in
  memory: do that only with full_memory. About 25 s each step. Headers and
  libraries come from C:\TC\TURBOC.CFG (C:\TC\INCLUDE, C:\TC\LIB); conio.h,
  dos.h, bios.h and graphics.h are there. "Out of memory" while compiling:
  split big functions. TC.EXE is the IDE: it needs a keyboard, so it is for
  the user, not for you.
- C:\DEVEL\BCC\BIN\BCC -o x.com x.c
  Bruce's C: K&R C, small .COM files. File names MUST be lowercase or it
  silently skips compiling. Slow: about 80 s for hello. Prefer TCC.

BASIC
- GWBASIC X.BAS
  GW-BASIC (Microsoft's 1983 source, MIT licence). End every program with
  SYSTEM, or it waits at Ok for a keyboard that never comes. PRINT goes to
  the screen, not to redirected output; to capture results write a file:
  OPEN "O",#1,"OUT.TXT" : PRINT #1, ... : CLOSE #1, then read OUT.TXT.
  About 6 s.

DEBUGGING
- LDEBUG X.COM < SCRIPT.TXT
  lDebug, a stronger FreeDOS DEBUG: the same commands (a, u, d, t, g, q),
  and it stops cleanly at the end of the script. Manual (large):
  C:\DEVEL\DOC\LDEBUG\LDEBUG.TXT. Plain DEBUG still works too.
