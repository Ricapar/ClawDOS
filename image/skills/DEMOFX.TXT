CGA demo effects: read before making fast graphics or demos
The rules below always apply; for details read the topic files in
C:\DEVEL\DOC\DEMOFX (read with lines 200: each is under 100 lines).
Working example: C:\TESTS\DEMO\RASTER.ASM (polled raster bars, tested).
Sources and the full research: 8088 MPH and Area 5150 write-ups.

THE MACHINE: IBM 5160, 8088 at 4.77 MHz, IBM CGA, IBM 5153 RGBI monitor.
- RGBI, NOT composite: no artifact colours, no 1024/512/256-colour modes,
  no 160x200 "composite 16 colours". 16 fixed RGBI colours (0-15) only.
- 1 scanline = 304 CPU cycles = 76 PIT ticks; 262 lines = 19912 PIT ticks
  per 60 Hz frame. Everything is counted against that.
- Assume nothing is fast: a byte costs 4 cycles to fetch, a CGA RAM access
  waits 3-8 more. Budget each frame in cycles before writing code.

RULES
1. Assemble with TINYASM (NASM syntax, org 0x100, .COM). 8086 only: no
   push imm, no shl r,imm>1, no pusha, no movzx. Out-of-range jcc: invert
   the test and jmp. Write the effect in asm; C only for setup or tables.
2. The program must end by itself (nobody may be at the keyboard): run a
   fixed number of frames (60 = 1 s), and also stop early on a key
   (in al,0x60 / test al,0x80 or INT 16h AH=1, checked once per frame).
3. Leave the machine as you found it: restore PIT 0 (count 0), PIT 1
   (count 18) if changed, every interrupt vector you hooked, the 8259 mask,
   and the speaker (port 61h). ClawDOS sets text mode again after a run,
   but its network stack and clock keep running beside your program.
4. Keep interrupts off only for a frame at a time (cli at the top of the
   visible area, sti in vertical blank): the network card and the BIOS
   clock need servicing. Cycle-exact effects need the NE2000 quiet anyway.
5. 80-column text mode snows when the CPU touches CGA RAM during display.
   Write VRAM in 40-column text or graphics modes, or only in blanking.
6. Prefer changing CRTC registers and the colour register (no snow, no
   VRAM bandwidth) over redrawing memory.
7. Nobody can watch for you, but you can look: run with screenshot true
   for a picture of the screen the program leaves, or shot_at N for one
   N seconds into the run (a program that sets text mode on exit). It
   is a PNG of video memory with the colours the BIOS set (modes 4, 5,
   6); if you wrote 3D8h/3D9h yourself, give shot_mode and shot_color:
   the 3D9h value; in 320x200 bits 0-3 are the background, bit 4 the
   bright foreground, bit 5 the palette (0 green/red/brown, 1
   cyan/magenta/white); +64 if you turned the colour burst off in 3D8h
   bit 2 (mode 5's cyan/red/white; a mode 5 set through the BIOS is seen
   without it). In 640x200 bits 0-3 are the foreground colour. The copy
   at shot_at goes to a 16 KB block of conventional memory, never EMS,
   so a program may use EMS freely. It reads memory from offset 0: a moved
   CRTC start address or a page flip is not in it, nor per-line
   register changes (raster bars, splits).
   Each picture adds ~22 KB to the chat: look when it matters. Also have
   the program measure itself (PIT ticks per frame, frames dropped) and
   print the numbers when it ends.
8. Use full_memory for big tables or code (over ~150 KB).
